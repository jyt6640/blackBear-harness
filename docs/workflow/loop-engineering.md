# Loop Engineering

코드라는 산출물을 근거로 철학 준수를 점수화하고,
낮은 항목의 프롬프트(카드 지침, 역할 docs, 정본)를 계속 개선하는 루프를 정의한다.

지침이 잘 지켜지는지 감이 아니라 통계로 보고,
프롬프트 개선의 방향을 점수가 알려주게 한다.

---

## 루프

    ① 채점 → ② 집계 → ③ 진단 → ④ 개선 제안 → ⑤ 승인·반영 → (다음 카드) → ①

### ① 채점 (카드마다, Review 단계)

- Review Agent가 판정과 함께 `next-step/work/<작업명>/06-scorecard.md`를 작성한다.
- 점수표 항목의 정본은 [templates/06-scorecard.md](../../templates/06-scorecard.md)다.
  항목은 docs의 철학·decision에서 도출되었고, 각 행이 출처를 가리킨다.
- 항목별 2 / 1 / 0의 경계와 전형적 위반은 [loop-scoring-criteria.md](./loop-scoring-criteria.md)가 정의한다.
  기준이 모호해서 채점이 흔들리면 점수가 아니라 기준 문서를 고친다.
- 점수는 diff와 단계 보고서를 근거로 매기고, 근거에 코드 위치를 인용한다.
- 완료된 점수표는 산출물 체인과 함께 `next-step/history/`로 이동해 누적된다.

### ② 집계 (백로그 완료 시 또는 카드 5장마다)

    scripts/loop/aggregate-scores.sh

- history의 점수표를 항목별 평균 / 채점 수 / 감점 카드로 집계한다.
- 평균이 낮은 항목이 개선 후보다.

### ③ 진단

낮은 항목의 원인을 둘로 구분한다. 처방이 다르다.

- 지침 부족·모호: 카드의 적용 지침이나 역할 docs가 그 항목을 충분히 구체적으로
  말하지 않았다. → 프롬프트를 고친다.
- 지침 위반: 지침은 명확한데 안 지켜졌다. → 해당 항목을 카드의 금지 사항으로
  승격하거나, 기계 판정이 가능하면 스크립트 검사로 강제한다.
  → [enforcement-by-script](../decisions/accepted/enforcement-by-script.md)

점수표의 "최저 항목 메모"가 이 구분의 1차 입력이다.

### ④ 개선 제안 (/loop-improve)

- 낮은 항목의 출처 정본, 역할 docs, 카드 템플릿의 적용 지침을 함께 본다.
- 개선안을 draft decision 또는 문서 수정 제안으로 만든다. 자동 반영하지 않는다.
- 제안에는 기대 효과를 적는다: "이 문구를 추가하면 다음 집계에서 SX 평균이 오를 것".

### ⑤ 승인·반영

- 사람이 확인한 제안만 정본 / 템플릿 / 역할 docs에 반영한다.
- 반영 효과는 다음 집계에서 측정한다. 오르지 않으면 진단(③)이 틀린 것이다.

---

## 강제 수준

- 채점 생성은 게이트로 강제된다.
  - 자동 모드: run-stage가 Review 후 `06-scorecard.md` 미생성 시 FAIL.
  - 사용자 릴레이: 마무리 단계가 `check-artifact-chain.sh`를 실행해
    점수표 없는 카드를 history로 이동시키지 않고,
    verify(pre-commit)가 점수표 없는 history 카드의 커밋을 차단한다.
- 집계와 개선 제안은 운영 절차다. 백로그 완료 시 오케스트레이터가
  /loop-improve 실행을 정지 멘트로 요청하지만, 실행 여부는 사람이 정한다.
- 채점의 내용 충실도(근거 인용)는 기계 판정 불가이므로 지침과 재검토 신호로 관리한다.

---

## 운영 기준

- 점수는 프롬프트 품질의 신호이지 작업자 처벌이 아니다.
  낮은 점수의 1차 용의자는 항상 지침이다.
- 점수표 항목의 추가·삭제·문구 변경은 draft decision을 거친다.
  항목이 바뀌면 이전 점수와의 비교 가능성이 끊기므로 변경 시점을 기록한다.
- 전 항목 만점이 계속되면 좋은 신호가 아니라 항목이 무뎌진 신호다.
  기준을 올리거나 항목을 세분화한다.
- N/A가 항상 많은 항목은 점수표가 아니라 카드 분해가 문제일 수 있다.

---

## 판단 기준

루프 운영이 헷갈리면 아래 질문으로 판단한다.

- 점수에 코드 위치 근거가 있는가? (없으면 채점이 형식화된 것)
- 낮은 항목의 원인이 지침 부족인지 위반인지 구분했는가?
- 개선이 측정 가능한 기대 효과를 명시했는가?
- 반영 후 다음 집계로 효과를 확인했는가?
