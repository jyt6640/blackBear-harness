# Local LLM Agent Orchestration

## 상태

accepted

---

## 문제 상황

현재 사용자 릴레이 모드는 Test → Feat → Refactor → Review 단계마다 상위 모델이
역할 하네스와 프로젝트 문맥을 다시 읽는다. 산출물 경계는 잘 지켜지지만 상위 모델
토큰을 빠르게 소비한다.

검토할 선택지는 다음과 같다.

- 상위 모델 한 개가 모든 단계를 계속 수행한다.
- Codex 내장 sub-agent 또는 별도 thread가 각 단계를 수행한다.
- 로컬 LLM을 Codex CLI의 OSS provider로 호출해 각 단계를 수행한다.
- 역할마다 별도 worktree를 만들거나, 카드마다 하나의 worktree를 공유한다.

로컬 모델 서버와 모델은 프로젝트 및 실행 환경마다 달라질 수 있다.
하네스는 특정 서버, 모델, 주소를 고정하지 않아야 한다.

---

## 선택한 방향

카드마다 하나의 전용 branch와 worktree를 만들고,
Test → Feat → Refactor → Review를 같은 worktree에서 직렬 실행한다.

오케스트레이터는 단계 상태와 Git 기준점을 관리하고, 역할 에이전트는 자기
`agents/<role>/AGENTS.md`, 작업 카드, 이전 단계 산출물만 입력으로 받는다.

로컬 모델 호출은 특정 서버 SDK에 결합하지 않고 Codex CLI 어댑터로 감싼다.

```bash
codex exec --ephemeral -C <isolated-agent-workspace> --add-dir <card-worktree> -
```

provider와 model은 저장소 코드가 아니라 Codex profile로 주입한다.
실행기는 격리된 `CODEX_HOME`을 사용해 사용자 전역 plugin, skill, root
`AGENTS.md`가 역할 입력에 섞이지 않게 한다.

단계 에이전트는 다음 단계를 직접 호출하지 않는다. 결과와 종료 상태를 반환하면
오케스트레이터가 게이트를 검사하고 다음 에이전트를 호출한다.

병렬 실행은 서로 다른 카드 사이에서만 허용한다. 한 카드 안의 Test, Feat,
Refactor는 선형 커밋 체인을 유지하기 위해 직렬 실행한다.

---

## 선택 이유

### 기존 산출물 계약 재사용

`00-task-card.md`부터 `03-review-report.md`까지의 산출물이 이미 모델 사이의
인터페이스다. 새로운 메시지 프로토콜보다 기존 파일 계약을 사용하는 편이 변경
범위가 작다.

### 커밋 체인 보존

현재 검증은 시작 commit 이후의 test → feat → refactor 선형 이력을 전제로 한다.
카드별 단일 worktree는 단계별 cherry-pick과 보고서 해시 재작성 없이 이 전제를
유지한다.

### 모델 서버 교체 가능성

Codex CLI가 Ollama와 LM Studio를 같은 실행 표면으로 제공한다. 저장소의
오케스트레이터가 서버별 API 차이를 직접 알지 않아도 된다.

### 입력 범위 통제

작업 카드가 공통 상위 문서와 역할별 추가 문서를 명시한다. 역할 에이전트는
자기 하네스와 이 목록만 문서 입력으로 사용하므로 전체 하네스를 매번 읽지 않는다.

---

## 트레이드오프

- 상위 모델의 입력 토큰은 줄지만 전체 추론 시간과 로컬 자원 사용량은 늘어난다.
- 카드마다 worktree를 생성하고 정리하는 상태 관리가 추가된다.
- Codex CLI에 실행 어댑터를 의존한다.
- 로컬 모델이 긴 하네스를 그대로 읽으면 토큰 절감 효과가 작아질 수 있어,
  작업 카드와 역할별 필수 문서를 더 작게 컴파일해야 한다.
- 같은 카드에서 역할을 병렬 실행하지 못한다.
- 로컬 모델마다 tool use와 장문 지시 준수 품질이 달라 별도 적합성 검증이 필요하다.

---

## 현재 판단

자동 모드는 사용자 릴레이를 제거하지 않고 fallback으로 유지한다.
역할별 완료 조건의 "사용자에게 다음 스킬 요청"은 자동 모드에서 "결과 반환 후
종료"로 해석하도록 실행 모드별 계약을 분리한다.

로컬 provider는 실제 카드 실행 전에 연결, context 길이, shell tool 호출을
검증해야 한다.

---

## 재검토 신호

- shadow review에서 상위 모델 검토보다 치명적 누락이 반복된다.
- 로컬 모델 단계 성공률이 기준보다 낮아 재시도 비용이 토큰 절감보다 커진다.
- 단계별 입력을 줄이면서 accepted decision이 누락된다.
- 카드별 worktree 생성과 정리 비용이 작업 자체보다 커진다.
- 선형 커밋 체인 대신 독립 구현 비교가 기본 실행 방식이 된다.
- Codex CLI의 OSS provider 인터페이스가 변경된다.
