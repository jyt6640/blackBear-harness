# Backlog Loop With Worktree

## 상태

accepted

---

## 문제 상황

품질 기계(컴파일 카드, 산출물 게이트, 점수표, 역할 분리)는 갖췄지만
처리량 인프라가 없었다.

- 카드는 직렬이었다. 백로그가 길면 한 장씩 순서대로.
- 카드 사이마다 사람이 /orchestrate를 호출해야 했다.
- 특히 로컬 LLM은 느려서, 한 카드를 사람이 기다리면 벽시계가 그대로 손해다.

느린 모델을 사람이 기다리면 안 된다. 던져놓고 떠나야 한다.

---

## 선택한 방향

백로그 무인 순회 루프를 둔다: `scripts/local-agent/run-backlog.sh`.

- 백로그의 `대기` 카드를 읽어 카드마다 git worktree로 격리한다.
- `--parallel N`으로 동시에 N개 worktree를 돌린다 (기본 1=직렬).
- 각 티켓은 `run-pipeline.sh`로 돌고, 기본은 `--hybrid`(구현=로컬, Review=강모델).
  `--full-local`로 Review까지 로컬로 돌릴 수 있다.
- 게이트, 재시도 한도, 산출물 체인을 그대로 따른다.
- 결과: OK / BLOCKED / FAIL을 카드별 로그와 함께 보고한다.

worktree 격리의 효과:

- 병렬 카드의 커밋이 섞이지 않는다 (각자 다른 worktree + branch).
- 한 카드가 실패하거나 깨진 상태로 남아도 다른 카드와 메인 트리에 번지지 않는다.
- 로컬 LLM은 비용이 0이라 병렬 worktree를 여럿 돌려도 추가 비용이 없다.

---

## 선택 이유

### 느림을 병렬로 흡수

가장 느린 카드 한 장의 시간 안에 N장이 끝난다.
"느려서 답답하다"의 현실적 해법은 무인 + 병렬이다.

### 품질을 안 내리고 처리량을 얻음

각 worktree가 우리 카드 릴레이와 게이트(verify green-bar, 점수표)를
그대로 통과해야 하므로, 처리량을 늘려도 품질 하한이 유지된다.

---

## 트레이드오프

### 반려 루프가 비싸짐

느린 모델이 한 카드에서 여러 번 반려되면 시간이 크게 날아간다.
`--max-retries`를 낮게 잡고, 한도를 넘으면 BLOCKED로 사람에게 넘긴다.
무인 루프의 "밤새 헛돌기"를 막는 안전판이다.

### 공유 자원 충돌

병렬 카드가 동시에 draft decision을 만들거나 하네스를 건드리면 충돌한다.
병렬로 돌리는 카드는 decision-독립이어야 한다.
충돌 가능성이 있으면 직렬(--parallel 1)로 돌린다.

### 완료는 여전히 사람 게이트

루프는 카드를 OK까지 굴리지만, history 이동과 PR/merge는 사람이 한다.
무인은 throughput 층이고, 최종 승격은 사람이 판단한다.

---

## 현재 판단

세 실행 층을 둔다.

- 사용자 릴레이 (기본): 카드마다 사람 게이트. 품질 안전.
- run-pipeline: 카드 하나 무인 (hybrid 권장).
- run-backlog: 백로그 무인 순회 + worktree 병렬. 백로그가 길고
  무인으로 굴리고 싶을 때 켠다.

기본은 여전히 사람 게이트다. 무인 병렬은 옵션이다.

---

## 재검토 신호

- 병렬 카드의 충돌이 잦아 직렬로만 돌리게 된다.
- 반려 루프가 길어 무인 throughput 이득이 사라진다.
- worktree 정리(remove)가 실패해 디스크에 잔재가 쌓인다.
- BLOCKED 카드가 누적되어 사람 검토 큐가 밀린다.
