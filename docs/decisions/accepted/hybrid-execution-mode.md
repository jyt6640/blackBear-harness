# Hybrid Execution Mode

## 상태

accepted

---

## 문제 상황

실행 구성에는 세 가지가 있다.

- 단일 강모델이 전 역할을 수행 (품질 높음, 비용 비쌈, 자기 채점 편향)
- 로컬 LLM이 전 역할을 수행 (비용 쌈, 품질 낮음, 독립 리뷰는 가능)
- 둘의 혼합

로컬 전 역할 모드의 유일한 품질 우위는 독립 리뷰어다.
하지만 같은 모델이 테스트 / 구현 / 리뷰를 모두 하면 자기 숙제를 자기가 채점한다.
반대로 단일 강모델 전 역할은 품질은 높지만 이 편향을 그대로 가진다.

---

## 선택한 방향

하이브리드 실행 모드를 둔다.

- Test / Feat / Refactor: 로컬 LLM이 실행한다 (비용 차익).
  시행착오 루프가 가장 많은 구현 잡일을 로컬로 내린다.
- Review: 강모델(오케스트레이터, Claude)이 실행한다 (독립 리뷰).
  구현 모델과 리뷰 모델을 분리해 자기 채점 편향을 제거한다.
- 카드 컴파일도 강모델이 한다. 카드 규칙이 정확해야 로컬 역할이 따른다.
  → [task-card-compiles-rules](./task-card-compiles-rules.md)

실행: `scripts/local-agent/run-pipeline.sh <작업명> --profile <p> --hybrid`
구현 3단계 후 멈추고, 강모델에서 `/review`로 독립 리뷰를 받는다.

---

## 선택 이유

### 비용 차익과 독립 리뷰를 동시에

구현 잡일은 게이트(산출물 / 커밋 / 카드 컴파일)로 검증되므로
로컬 LLM에 내려도 위반이 기계적으로 잡힌다.
판단이 무거운 Review만 강모델로 분리해 비용과 독립성을 함께 얻는다.

### 카드 컴파일이 전제를 충족시킴

강한 오케스트레이터가 규칙을 카드로 컴파일하므로
약한 로컬 역할이 따를 기준이 정확하다.
이 분업이 신뢰 가능해진 뒤에야 하이브리드가 성립한다.

---

## 트레이드오프

### 모드 선택 비용

작업 난도와 비용 목표에 따라 단일 / 로컬 / 하이브리드를 골라야 한다.
기본은 품질 안전한 사용자 릴레이(단일 강모델)이고,
하이브리드는 비용 절감이 필요할 때 선택한다.

### 핸드오프 경계 증가

구현(로컬)과 리뷰(강모델) 사이에 모델이 바뀐다.
산출물 핸드오프가 이 경계를 견디도록 설계됐으므로 추가 비용은 작다.
→ [agent-handoff-by-artifact](./agent-handoff-by-artifact.md)

---

## 현재 판단

세 구성을 모두 둔다. 선택 기준:

- 품질 최우선 / 비용 무관: 사용자 릴레이 (단일 강모델).
- 비용 최우선 / 품질 감수: 로컬 전 역할.
- 균형 (권장): 하이브리드 — 오케스트레이터 + Review는 강모델, 구현 3단계는 로컬.

어느 구성이 유리한지는 같은 카드를 모드별로 돌려 토큰 / 반려율 / wall-clock으로 측정한다.

---

## 재검토 신호

- 로컬 구현의 반려율이 높아 하이브리드 비용 차익이 사라진다.
- 강모델 Review가 로컬 구현의 맥락을 산출물만으로 못 따라간다.
- 모드 선택이 매번 고민거리가 되어 기본값이 흔들린다.
