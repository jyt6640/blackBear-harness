# Cross-Tool Adapter Layer

## 상태

accepted

---

## 문제 상황

이 하네스는 Claude Code, Codex, Cursor, Gemini 등 여러 AI 코딩 에이전트에서
재사용되는 것이 목표다.

도구마다 진입 규약이 다르다.

- Codex / Cursor / Gemini CLI 등은 루트 `AGENTS.md`(agents.md 표준)를 읽는다.
- Claude Code는 `CLAUDE.md`와 `.claude/skills/`를 읽는다.
- Cursor는 `.cursor/rules/*.mdc`를 읽는다.
- Gemini는 `GEMINI.md`를 읽는다.

각 도구 규약마다 규칙 본문을 복제하면, 규칙이 바뀔 때 N개의 파일이 어긋난다.
이 저장소에서 이미 같은 종류의 드리프트(규칙 복제, 경로 불일치)가 발생한 적 있다.

---

## 선택한 방향

**one canon, N adapters.**

정본은 도구 무관하게 한 벌만 둔다.

- `AGENTS.md` (라우터 진입점)
- `agents/` (역할 정본)
- `docs/` (규칙·가치·결정·참조)
- `templates/` (산출물 정본)
- `scripts/` (기계 강제)

도구별 어댑터는 정본을 **복제하지 않고**, 정본 파일을 읽도록 안내하는
**얇은 포인터**만 둔다.

- `CLAUDE.md` → `AGENTS.md`를 읽도록 안내
- `.claude/skills/<role>/SKILL.md` → `agents/<role>/AGENTS.md`를 읽도록 안내
- `.cursor/rules/*.mdc` → 해당 정본 docs를 읽도록 안내
- `GEMINI.md` → `AGENTS.md`를 읽도록 안내

어댑터는 트리거(언제 이 역할을 시작하는가)와 정본 경로만 담는다.
규칙·철학·판단 기준은 한 글자도 어댑터에 쓰지 않는다.

---

## 선택 이유

### 단일 출처

규칙이 바뀌면 정본 한 곳만 고친다. 어댑터는 경로만 가리키므로 갱신이 필요 없다.

### 도구 비종속

정본(`AGENTS.md`+`agents/`+`docs/`+`templates/`+`scripts/`)은 어떤 도구에도
종속되지 않는 순수 마크다운·bash다. 새 도구가 생기면 어댑터 한 벌만 추가한다.

### 강제는 도구 밖에서

`scripts/`는 순수 bash + git hook으로 동작한다. Claude hook 같은 도구 전용
메커니즘에 의존하지 않으므로 모든 도구에서 동일하게 강제된다.

---

## 트레이드오프

### 한 단계 우회

어댑터를 읽은 도구는 다시 정본을 열어야 한다. 직접 본문을 박는 것보다
한 번의 파일 열기가 더 든다. 단일 출처의 이득이 이 비용보다 크다.

### 어댑터 드리프트 위험

어댑터에 본문이 새어 들어갈 수 있다. 이를 `scripts/check-adapter-sync`로
기계 검사한다(어댑터가 정본을 참조만 하는지, 본문을 복제하지 않았는지).

---

## 현재 판단

정본과 어댑터의 책임을 절대 섞지 않는다.
어댑터에서 규칙을 발견하면 위반으로 보고 정본으로 옮긴 뒤 어댑터는 포인터로 되돌린다.

---

## 재검토 신호

- 어댑터에 규칙 본문이 반복해서 새어 들어간다.
- 특정 도구가 포인터 방식을 지원하지 못해 본문 복제가 불가피해진다.
- 정본 경로 구조가 바뀌어 어댑터 다수를 동시에 수정해야 한다.
