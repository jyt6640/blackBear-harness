# Skill As Thin Launcher

## 상태

accepted

---

## 문제 상황

하네스 절차(인터뷰, draft decision 작성, base 동기화)를 Claude Code 스킬로 만들면
트리거가 기계화되고, 절차가 필요할 때만 컨텍스트에 로드된다.

하지만 스킬 본문에 절차 내용을 복사하면
md 문서와 스킬이라는 두 정본이 생겨 드리프트가 재발한다.

---

## 선택한 방향

스킬은 얇은 런처로만 만든다.

스킬 본문에는 아래만 담는다.

- 호출 트리거 (description)
- 정본 문서를 읽고 따르라는 지시
- 실행 세부 (산출 경로, 확인 절차, base 밖에서 실행 시 경로 해석)

절차의 내용은 항상 docs/ 문서가 정본이다.
스킬에 절차 내용을 복사하지 않는다.

---

## 선택 이유

### 드리프트 방지

절차가 바뀌면 문서만 고치면 된다.
스킬은 문서를 가리킬 뿐이므로 함께 고칠 것이 없다.

### 에이전트 호환

스킬은 Claude Code 전용이지만 정본이 md이므로,
AGENTS.md만 읽는 다른 에이전트에서도 하네스가 동일하게 동작한다.

---

## 현재 스킬

`.claude/skills/`에 둔다.

- harness-interview: 인터뷰 실행 → 프로젝트 하네스 생성
- draft-decision: 논의 / 관찰을 draft decision으로 작성
- harness-sync: base 갱신 시 프로젝트 하네스 재검토
- orchestrate: 작업 분할과 카드 컴파일 후 정지, 릴레이 시작
- test-agent: 작업 카드의 기대 행위를 실패 테스트로 표현
- feat-agent: 실패 테스트를 통과시키는 최소 구현
- refactor-agent: public behavior 변경 없는 구조 개선
- review-agent: 작업 산출물과 diff를 승인 / 반려

---

## 트레이드오프

스킬 호출 후 정본 문서를 읽는 단계가 한 번 더 있다.
즉시 실행보다 약간 느리지만 정본 일원화가 더 중요하다.

---

## 재검토 신호

- 스킬 본문이 길어지며 절차 내용을 담기 시작한다.
- 문서와 스킬의 지시가 어긋난다.
- 같은 절차를 안내하는 문서와 스킬의 트리거 조건이 달라진다.
