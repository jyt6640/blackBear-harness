# Task Card Compiles Rules

## 상태

accepted

---

## 문제 상황

역할 에이전트가 따라야 할 상위 docs는 수십 개다.
역할 AGENTS.md의 입력 목록과 자동 모드 프롬프트는 그 docs의 경로만 나열했고,
게이트는 파일 존재만 검사했다.

그 결과 "읽어야 할 문서"가 "검증 가능한 규칙"으로 바뀌는 고리가 끊겨,
역할 에이전트(특히 로컬 LLM, 컨텍스트 제한)가 상위 원칙을 정독하지 않고
자기 기본 지식으로 대체하는 위반이 가능했다. 위반은 Review에서야 잡혀
구현 시간이 낭비됐다.

---

## 선택한 방향

오케스트레이터가 상위 docs 규칙을 작업 카드에 카드별로 컴파일한다.

- `00-task-card.md`의 `이번 작업 컴파일 규칙` 섹션에 이번 작업에 적용되는 규칙을
  출처(decision / 문서)와 함께 적는다. 템플릿 placeholder를 남기지 않는다.
- 이 규칙이 역할 에이전트의 1차 구속 계약이다. 역할 에이전트는 카드 규칙 +
  자기 역할 docs를 기준으로 실행하고, 모호할 때만 출처 정본을 확인한다.
- 강제: `scripts/check-task-card.sh`가 placeholder 잔존과 출처 인용(2개 이상)을
  검사하고, 각 역할 `enforce-workflow.sh`가 단계 시작 전에 이를 실행한다.
- 자동 모드: `run-stage.sh`가 카드 경로가 아니라 카드 본문을 프롬프트에 주입한다.

이 방향은 두 모드 모두에 적용된다. 카드는 단독 모드와 자동 모드가 공유하는
실행 입력이기 때문이다.

---

## 선택 이유

### 읽기를 검증 가능한 규칙으로

"수십 개 docs를 읽었는가"는 게이트로 검증할 수 없지만,
"이번 작업 규칙이 출처와 함께 카드에 컴파일됐는가"는 검증할 수 있다.

### 컨텍스트 절약과 명제 일치

강한 모델(오케스트레이터)이 한 번 컴파일하면 역할 에이전트는
카드만 따르면 된다. "하네스를 작업 카드로 컴파일해 전달하고,
판단 체계형 하네스를 읽혀 판단시키지 않는다"는 명제의 미완성 부분을 채운다.

### 드리프트 경계

카드 컴파일은 철학을 복사하는 행위지만, 카드는 `next-step/work`의
휘발성 산출물(완료 후 history로 이동)이라 영구 정본이 아니다.
각 규칙이 출처를 인용하는 한 단기 컴파일 결과로 허용된다.
영구 문서가 되는 순간만 드리프트 위험이다.

---

## 트레이드오프

### 오케스트레이터 컴파일 비용

카드마다 관련 규칙을 골라 출처와 함께 적는 비용이 든다.
대신 역할 단계의 위반과 재작업이 줄어든다.

### 컴파일 누락 위험

오케스트레이터가 관련 규칙을 빠뜨리면 카드에 안 적힌 원칙은 여전히 약하다.
점수표 루프가 사후에 이를 잡아 프롬프트(컴파일 기준)를 개선한다.

---

## 현재 판단

카드 컴파일 규칙은 게이트로 강제하고(존재·출처 인용),
컴파일 내용의 충실도는 점수표 루프와 Review가 사후 검증한다.
런타임 예방(카드 컴파일)과 사후 탐지(점수표)는 상보적이다.

---

## 재검토 신호

- 컴파일 규칙이 형식적으로 채워지고 역할 에이전트가 출처를 다시 정독한다.
- 같은 항목이 점수표에서 반복 감점된다 (컴파일 기준 부족).
- 카드 컴파일 비용이 작업 자체보다 커진다.
