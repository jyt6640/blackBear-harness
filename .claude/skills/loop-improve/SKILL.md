# Loop Improve 실행

이 스킬은 얇은 런처다. 절차의 정본은 문서에 있다.

1. 정본을 읽는다: [docs/workflow/loop-engineering.md](../../../docs/workflow/loop-engineering.md)
   (base 저장소 밖이면 프로젝트 AGENTS.md의 base 선언 경로에서 찾는다)

2. 집계한다.

       scripts/loop/aggregate-scores.sh

   집계할 점수표가 없으면 멈추고, 카드가 history에 쌓인 뒤 다시 실행하도록 안내한다.

3. 개선 후보 항목마다 진단한다.

   - 감점 카드의 05-scorecard 근거와 단계 보고서를 읽는다.
   - 원인을 구분한다: 지침 부족·모호 / 지침 위반.
   - 항목의 출처 정본, 채점 기준(docs/workflow/loop-scoring-criteria.md), 관련 역할 docs, 카드 템플릿의 적용 지침을 함께 확인한다.
   - 카드 간 점수가 일관되지 않은 항목은 지침이 아니라 채점 기준의 경계가 모호한 것이다. 기준 문서를 개선 대상에 포함한다.

4. 개선을 제안하고 멈춘다. 자동으로 반영하지 않는다.

   - 지침 부족 → 카드 템플릿 적용 지침 / 역할 docs / 정본의 구체 문구 수정안
   - 지침 위반 → 금지 사항 승격 또는 기계 판정 가능하면 스크립트 검사 추가안
   - 각 제안에 기대 효과를 적는다: "다음 집계에서 어떤 항목의 평균이 오를 것"
   - 정본·템플릿 변경이 필요한 제안은 /draft-decision 형식으로 작성한다.

5. 사람이 승인한 제안만 반영하고, 효과는 다음 집계에서 확인한다.
