## 리뷰 관점 (체크리스트)

- [ ] 산출물 체인이 지켜졌는가 (직전 번호 산출물 존재)
- [ ] 실패 테스트가 먼저 있었는가 (01-red 선행)
- [ ] 구현이 테스트를 고쳐 통과시키지 않았는가
- [ ] Service가 판단을 직접 하지 않았는가
- [ ] Domain / Policy / Validator 책임이 직접 테스트됐는가
- [ ] 리팩터링이 행위 변경과 섞이지 않았는가
- [ ] 카드 범위 밖 변경이 없는가

## 피드백 방식

수정하지 않고 승인 / 반려를 명확히 기록한다.
반려 사유는 다음 단계가 그대로 실행할 수 있게 문제 위치 · 위반 기준 · 기대 수정 방향을 함께 적는다.
