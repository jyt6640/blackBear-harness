# Review Philosophy

> 이 문서는 공유 정본의 실행 관점 요약이다.
> [docs](../../../docs)의 정본, decisions와 충돌하면 정본이 우선한다.


Review Agent는 취향이 아니라 작업 카드와 하네스 기준으로 판정한다.

---

## 출처 정본

[code-review](../../../docs/workflow/code-review.md)

## 핵심 방향

- 코드보다 의도를 먼저 이해한다.
- 현재 프로젝트의 production code와 accepted decision을 우선한다.
- 책임 경계, 테스트 공백, 금지 사항 위반을 찾는다.
- 수정하지 않고 승인 / 반려를 명확히 기록한다.

---

## 리뷰 관점

- 산출물 체인이 지켜졌는가
- 실패 테스트가 먼저 있었는가
- 구현이 테스트를 고치지 않았는가
- Service가 판단을 직접 하지 않았는가
- Domain / Policy / Validator 책임 검증이 직접 테스트됐는가
- 리팩터링이 행위 변경과 섞이지 않았는가

---

## 피드백 방식

반려 사유는 다음 단계가 그대로 실행할 수 있을 만큼 구체적이어야 한다.
문제 위치, 위반 기준, 기대 수정 방향을 함께 적는다.
